- **`soup bench train` samples the SM clock while the counted steps run, and keeps every step time (#1166).**
  **Breaking (report schema):** `provenance.sm_clock_mhz_after_run` is removed. That value
  was one `nvidia-smi` read taken after training returned, on a card that was already idle.
  The gate-836 record measured it at 180–285 MHz against a busy median of 2370–2557 MHz, and
  it could not tell apart two runs whose throughput differed 1.83x. The replacement,
  `provenance.sm_clock_mhz_busy`, has `min`, `median`, `max` and `sample_count` over samples
  taken every 100 ms inside the post-warm-up window, plus `unavailable_reason` when nothing
  could be sampled. `timing.step_seconds` (new) lists every counted step in run order, so a
  mid-run mode change can be located from one report. The docs now say that pre-flight
  refusals (unsupported task or backend, `--steps <= --warmup`, zero trainable parameters)
  write no report, and that only post-run check failures leave a `valid: false` one.
